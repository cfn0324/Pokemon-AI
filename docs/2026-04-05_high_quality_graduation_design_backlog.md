# 2026-04-05 高质量毕业设计问题清单与阶段化重任务路线

## 1. 目标

这不是普通的 TODO，而是面向“高质量本科毕业设计 / 可支撑毕业论文答辩”的阶段化问题台账。

执行原则：

- 不一次性并行铺开所有问题。
- 每次只推进一个阶段性的重任务。
- 每个阶段都必须有明确产物、验收条件和证据文件。
- 后续改进以“增强论文说服力”为目标，而不是只增加代码量。

## 2. 当前总体判断

截至 2026-04-05，项目已经具备：

- 可运行的完整工程系统
- 稳定的自动化测试面
- 真实模型接入能力
- 基本可复现的 smoke 实验能力

但如果目标提升到“高质量毕业设计”，核心短板已经不再是“项目能不能跑”，而是：

- 真实 AI 参与证据是否足够强
- 多次重复运行是否稳定
- 关键剧情局部场景中的决策质量是否足够高
- 文档、证据、结论边界是否足够适合论文表达

## 3. 问题清单

### Q1. 缺少足够强的真实 AI 重复实验证据

优先级：`P0`

问题描述：

- 已有单次真实 AI 主导短程 smoke 证据，但过去缺少统一协议下的 3 至 5 组重复实验。
- 旧的长程 smoke 多数是 resilience evidence，不足以证明 AI 真正主导了决策。

为什么这是高质量毕设问题：

- 论文不能只依赖一份成功样例。
- 必须能够回答“在真实模型条件下，多次运行是否稳定、是否可重复”。

截至当前的最新进展：

- 已补齐批量实验脚本 `scripts/autonomous_smoke_batch.py`
- 已完成固定协议 3 次 batch
- 已发现并修复一次 `ConnectionResetError(10054)` 被误判为长期不可达、从而导致整段 run 被 fallback 吞噬的问题
- 修复后已完成单次 120 turn 复测和新的 3 次固定协议 batch

当前结论：

- 这一问题已从“无批量证据能力”推进到“有批量能力且已有第一轮正式证据”
- 但仍未达到“稳定拿到更强剧情里程碑”的标准，因此尚未完成

完成标准：

- 至少形成 3 至 5 组统一参数的真实 AI 实验
- 每组实验具有统一 checkpoint、统一模型、统一参数
- 至少 1 组达到强于 Oak Lab 原地循环的剧情里程碑，如 `got_pokedex` 或 `oak_got_parcel`

建议阶段：`Phase 2`

### Q2. Oak Lab 关键局部场景的 AI 决策质量仍然偏弱

优先级：`P0`

问题描述：

- 即使 AI 参与比例提升，Oak Lab 中仍然存在大量低效试探。
- 主要问题集中在 NPC 邻接、面向关系、交互触发与局部空间理解上。

为什么这是高质量毕设问题：

- 这是当前最有研究价值、也最能体现系统能力的失败点。
- 如果不解决，论文最多只能证明“AI 能参与”，很难证明“AI 能稳定推动剧情”。

当前结论：

- 经过 Phase 2 的批量实验，Oak Lab 局部瓶颈依然存在
- 这已经成为下一阶段最明确的主攻方向

完成标准：

- 明显减少 Oak Lab 局部循环和无效交互
- 真实 AI 条件下更高概率走出 Oak Lab 的关键剧情锁
- 至少拿到更强 milestone，如 `got_pokedex` 或 `oak_got_parcel`

建议阶段：`Phase 3`

### Q3. 缺少系统化消融实验

优先级：`P0`

问题描述：

- 当前已有多种模式和保护层，但尚未形成规范的对比实验矩阵。
- 论文还无法清晰回答“哪些模块真正有效、提升来自哪里”。

最低建议覆盖：

- `llm_primary_mode=false` vs `true`
- `ai_full_control_mode=false` vs `true`
- 是否启用增强导航摘要
- resilience-only run vs real-AI run

完成标准：

- 至少形成一张正式对比表
- 每个结论都能被实验记录直接支持

建议阶段：`Phase 4`

### Q4. 实验资产管理过去偏混乱，现已开始收束但仍未完全论文化

优先级：`P1`

问题描述：

- `tmp/` 下历史实验文件很多，旧报告命名和用途并不统一。
- resilience、real-AI、排障试验如果不分层，很容易被误用。

当前进展：

- 已新增 backlog、evidence index、phase assessment 三类文档
- 已新增批量实验输出目录与 manifest
- 新实验开始具备“原始 JSON + 汇总 Markdown + 参数/环境清单”的固定结构

当前结论：

- 这一问题已经显著改善，但还需要继续清理旧资产并保留最可信的一组正式证据

建议阶段：`Phase 1` 持续维护

### Q5. 文档体系仍需进一步论文化收束

优先级：`P1`

问题描述：

- 项目已有不少文档，但过去缺少真正面向论文与答辩的结构化索引。
- 需要把“评估、实验、路线图、阶段结论”真正串起来。

当前进展：

- 已形成 readiness assessment
- 已形成问题 backlog
- 已形成 evidence index
- 已形成 evaluation workflow
- 本轮新增了 Phase 2 阶段评估材料

当前结论：

- Phase 1 基线已达成
- 但最终 README、论文附录材料包、答辩版图表仍未完成

建议阶段：`Phase 1` 已完成基线，`Phase 5` 做最终收束

### Q6. 缺少论文级图表和可直接引用的材料包

优先级：`P1`

问题描述：

- 当前仓库更像研发仓库，而不是可直接写论文的材料包。
- 还缺结构图、模块图、实验表、失败案例分类图等。

完成标准：

- 至少输出一套可直接进入论文正文的图表与表格模板

建议阶段：`Phase 5`

### Q7. 真实 AI 运行代价与延迟统计还不够完整

优先级：`P2`

问题描述：

- 当前已有 `ai_latency_summary`，但还没有形成论文层面的效率分析维度。
- 还缺成本、超时比例、AI 占比与推进质量之间的系统分析。

完成标准：

- 形成统一的延迟 / 占比 / 推进质量统计表

建议阶段：`Phase 4`

### Q8. 最终论文结论边界仍需刻意收束

优先级：`P1`

问题描述：

- 若直接把结论写成“稳定自主完整通关”，当前证据远远撑不住。
- 更稳妥的定位仍应是“早期剧情可行性验证 + 局部瓶颈分析”。

完成标准：

- 在论文支持文档中固定最终题目建议、研究问题与结论边界

建议阶段：`Phase 5`

## 5. 当前执行策略

从当前这一轮起，推进策略更新为：

1. `Phase 1` 已完成，不再停留在纯文档规划。
2. 当前活跃阶段为 `Phase 2`，重点是“真实 AI 重复实验能力 + 证据质量”。
3. 在 `Phase 2` 未出现更强剧情里程碑前，不进入大规模消融与论文图表收尾。
4. 下一阶段只应推进 `Phase 3`，即 Oak Lab 局部决策质量提升，而不是继续堆积更多同质化 batch。

## 6. 当前结论

以“高质量毕业设计”为目标，当前最重要的事实已经很清楚：

- 项目不再缺工程可用性
- 项目已经具备真实 AI 重复实验能力
- 当前最强短板已收敛为：真实 AI 在 Oak Lab 关键局部场景中的稳定推进质量仍不足

因此，下一轮重任务不应再是泛泛补 bug，而应明确转入：

- Phase 3：Oak Lab 局部决策质量提升
