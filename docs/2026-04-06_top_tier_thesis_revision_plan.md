## 逐章修改

### 摘要

- 第一段保留任务意义，但压缩对“纯 AI”的价值宣称，避免一上来就把问题写成范式级突破
- 第二段必须把证据写成硬信息：主实验样本数、重复实验样本数、到达率、最远到达点、哪些属于结构化确认，哪些只属于视觉确认
- 删除“已经跨过关键门槛”“已经建立连续闭环”一类强结论，改成“初步显示”“在当前协议下观察到”
- 在中文摘要末尾主动承认边界：固定起点、早期剧情、RAM 特权观测、样本量有限

### Abstract

- 与中文摘要完全镜像，不要出现英文比中文更强或更弱的结论
- 明确 `n`、budget、success rate，而不是只写 narrative summary
- 避免使用 `establish verified continuity` 这类过强措辞，改成 `demonstrate evidence of`, `show preliminary reproducibility under`

### 第 1 章 绪论

- 重写 `1.2` 的问题陈述，不要把核心问题写成“纯 AI 决策是否已经成立”，而要写成两个可检验问题：
- `RQ1`：在限定协议下，系统能否在无外部接管的条件下完成非平凡早期剧情推进
- `RQ2`：哪些运行时支撑能提高此类推进的稳定性，同时不改变控制权归属
- 重写 `1.3` 的贡献，改成三条可审稿的贡献：
- `C1`：一个面向长时序 JRPG 的受审计运行时框架
- `C2`：一套区分控制权、剧情深度、时间线有效性的评估协议
- `C3`：在固定早期剧情任务上的存在性与初步可复现性结果
- 删除“证明纯 AI 路线已经成立”这种预设型措辞

### 第 2 章 相关工作与理论基础

- 把相关工作扩成至少四组，而不是主要围绕两篇文献转
- 建议分组：
- 长时序 LLM agent 与 memory/retrieval agent
- game-playing agent 与 game benchmark
- multimodal / embodied / tool-using agent
- auditability、reproducibility、runtime scaffolding 相关系统论文
- 每一组都要回答“本文继承了什么”“本文不做什么”“本文和它们的关键区别是什么”
- 减少内部材料在本章中的存在感，内部材料只作为实现出处，不作为理论依据
- 图 2-1 可以保留，但要把图注改得更客观，不要图注替正文下结论

### 第 3 章 任务定义与形式化描述

- 保留任务范围和里程碑定义，但把“里程碑链”与“可宣称边界”拆开写
- 单独加一个表：`Allowed Runtime Support vs. Disallowed Takeover`
- 表中至少列出：
- RAM 读取：允许
- 地图记忆：允许
- 状态摘要/任务笔记：允许
- 动作合法性检查：允许
- 方向补偿：有条件允许，需定义上限
- 同回合重试：有条件允许，需定义次数
- 微循环检测与风险规避：需要严格说明不会改写剧情路线
- 检查点恢复：不得进入主结果统计，或必须单独标注
- 将 `P_path`、`P_author`、“有效回合”“结构化确认”“视觉确认”给出精确定义，避免读者自行猜
- 删减或压缩那些没有支撑后续分析的形式化表达，只保留能对应实验表格和日志字段的定义

### 第 4 章 系统总体设计

- 新增一张系统配置表，至少包含：

- API 服务与地区
- 采样参数
- context window / max output
- timeout / retry / cooldown
- emulator 版本

### 第 5 章 核心方法与关键模块实现

- 当前最大风险是读者会认为这是“强工程扶手 + 强提示 + 特权状态”的系统，而不是纯 AI 决策研究
- 因此这一章必须主动承认并拆解扶手：
- 哪些是 observation scaffolding
- 哪些是 decision scaffolding
- 哪些是 execution stabilization
- 哪些可能被怀疑为 hidden policy
- 对故事引导和战斗引导，必须给出更规范的描述：
- 输入是什么
- 输出是什么
- 是模板化说明、规则文本还是动态摘要
- 是否依赖人工编写任务知识
- 最好加入一个最小示例，展示 prompt/state 如何从原始观测映射到任务化状态
- 加一段专门解释为什么 `ActionExecutor` 不构成策略接管，并用实验约束证明这个说法

### 第 6 章 实验设计与证据组织

- 本章必须从“证据组织”升级到“实验设计”
- 加一个实验协议总表，列出所有实验：
- 主实验
- 重复实验
- 长程平台实验
- 消融实验
- 基线实验
- 失败分析样本
- 每类实验要明确写出 `n`、起点、budget、终止条件、统计单位、是否纳入主结论
- 正文补齐统计计划：
- 报告成功率与到达率
- 报告均值、中位数、标准差或置信区间
- 说明是否做 bootstrap 或 exact binomial interval
- 如果样本量仍小，要显式承认 exploratory 而不是 confirmatory
- 视觉证据只能作为辅助，不应成为正文主要结果的替代品

### 第 7 章 实验结果与分析

- 这是当前最需要重写的一章
- 建议重构顺序：
- `7.1` 先给主结果总表
- `7.2` 再给基线对比
- `7.3` 再给消融
- `7.4` 再给失败分析
- `7.5` 最后才放视觉结果和案例图
- 现在的问题是：正文先讲故事，再讲结果，审稿人会怀疑你在用 narrative 掩盖统计薄弱
- 主结果表建议至少包含：
- 成功到达 `Route 1` 的比例
- 成功到达 `Viridian City` 的比例
- 成功进入 `Viridian Mart` 的比例
- 成功获得 `Oak's Parcel` 的比例
- 平均步数
- 平均请求数
- 平均时延
- 错误率或超时率
- `P_path`
- `P_author`
- 对 `83.46%` 这类数字，必须解释分母是什么，哪些回合被排除，为何排除
- 对 `1/3` 这类结果，不要写成“已经能够稳定复现”，只能写“观察到非零复现率”
- 失败分析要系统化，不要只给“包裹后商店停顿”这一种相对温和的例子

### 第 8 章 讨论、研究意义与扩展方向

- 当前章过于像 defense，而不像 discussion
- 新结构建议：

- `8.4` 外部有效性与可迁移性
- `8.5` 下一阶段实验计划
- 必须正面写的局限性：

- 样本量仍小
- RAM 属于特权观测
- 运行时故事引导含有环境知识

- 网络抖动会影响运行稳定性
- 这一章的价值不是证明你已经够强，而是证明你知道自己还不能声称什么
