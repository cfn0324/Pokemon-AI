# 毕业设计论文
## 面向长时序任务的直接决策型大语言模型游戏智能体
### 以《宝可梦 红》早期剧情自主推进为例

## 摘要

长时序游戏环境同时包含部分可观测状态、稀疏里程碑、菜单式交互、跨地图导航与长期目标维护，因此适合检验生成式模型是否能够在较长时间尺度上承担连续决策责任。与 `Arcade Learning Environment` 一类强调短时反应和局部控制的经典基准不同[1-2]，《宝可梦 红》的早期主线要求智能体在房间、城镇、道路、对话框、战斗菜单与剧情事件之间持续切换语义，并避免局部循环、错误交互和剧情锁死。

本文实现了一个运行于 `PyBoy` 模拟器上的大语言模型游戏智能体系统。系统采用"普通回合由主模型直接给出动作，运行时负责整理状态、约束执行并保留证据"的设计思路。围绕这一思路，项目实现了 RAM 语义状态提取、地图记忆、上下文压缩、动作合法化、同回合同观测重试、结构化日志与批量评估等模块，并将故事引导与战斗引导设计为可显式开关的支持文本，便于分别观察它们对推进过程的影响。本文将该研究对象界定为"直接决策型大语言模型游戏智能体"：普通回合动作由主模型直接生成，运行时只负责状态组织、执行稳定化和证据留存。基于这套系统，正文使用主模型直接决策回合占比、里程碑到达率、时间线有效性以及 AI 冷却回合、AI 调用错误回合等指标，对运行质量进行量化描述。

受限于外部模型服务成本与实验周期，本文主实验仅完成 `n=3` 的小样本批量复验，相应结论应理解为初步可重复性证据而非强统计主张。实验部分以主实验统一初始状态下的结构化复验为主，核心统计结论集中在完整引导条件、`120` 回合预算内的早期窗口：`3/3` 到达 1号道路，`2/3` 到达常磐市，`2/3` 进入常磐市友好商店；三次运行的主模型直接决策回合占比均为 `1.0`，时间线记录均有效。以 Wilson 区间计，1号道路到达率为 `100%`（95% CI: `43.9%-100.0%`），常磐市与常磐市友好商店到达率均为 `66.7%`（95% CI: `20.8%-93.9%`）。这表明系统在固定起点和固定预算下具备初步的可重复推进能力。作为补充，单次 `260` 回合长程运行保留了完整路径记录，也清楚暴露了外部模型服务波动对长程质量的影响：该次运行推进至 1号道路，主模型直接决策回合占比为 `0.6154`，期间出现 `94` 个 AI 冷却回合和 `6` 个 AI 调用错误回合。两组探索性模块分析表明，故事引导对早期路线形成更关键，而战斗引导在该窗口中主要改善战斗阶段的局部语义理解。总体而言，系统已经具备从大木博士研究所推进至常磐市友好商店的早期主线能力，并为分析更长时程中的限制因素提供了结构化依据。

**关键词**：长时序任务；游戏智能体；大语言模型；《宝可梦 红》；直接决策

## Abstract

Long-horizon game environments are useful testbeds for agent research because they couple partial observability, sparse milestones, menu-heavy interaction, map transitions, and long-term goal maintenance within a single task chain. Compared with short-horizon control benchmarks, early-story progression in `Pokemon Red` requires an agent to switch repeatedly across room navigation, town traversal, dialogue advancement, battle menus, and event-triggered state changes without external intervention.

This paper presents a large-language-model game agent running on the `PyBoy` emulator. The system centers ordinary-turn decisions on the main model and provides auditable runtime modules for RAM-based state extraction, map memory, context compression, action normalization, same-observation retries, structured logging, and batch evaluation. Story guidance and battle guidance are implemented as explicit, switchable support texts that can be analyzed separately. The target system is characterized as a direct-decision LLM game agent: ordinary-turn actions are generated directly by the main model, while the runtime is responsible for state organization, execution stabilization, and evidence logging. The paper uses the main-model direct-decision ratio, milestone reach rates, timeline-validity checks, and diagnostic counts for cooldown and AI-call-error turns as primary evidence.

Due to external model-service costs and experiment-cycle constraints, the main experiment comprises only `n=3` replicate runs; conclusions should be interpreted as preliminary repeatability evidence rather than strong statistical claims. Structured reverification from the standardized initial state yields the following core-window results under complete guidance within a 120-turn budget: all three trials reached `Route 1`, two reached `Viridian City`, and two entered `Viridian Mart`; all three achieved a main-model direct-decision ratio of `1.0` with valid timelines. A supplementary 260-turn stress trial preserved the same path-logging protocol and highlighted the effect of model-service instability on longer horizons, with a main-model direct-decision ratio of `0.6154`, `94` cooldown turns, and `6` AI-call-error turns. Exploratory module analyses suggest that story guidance is more important for early route formation, while battle guidance mainly improves local battle semantics within the current window. Together, these results establish an auditable system, a reproducible evaluation workflow, and a clear empirical basis for analyzing early-story progression under direct LLM decision-making.

**Keywords**: long-horizon tasks; game agents; large language models; Pokemon Red; direct decision

## 第 1 章 绪论

### 1.1 研究背景

生成式模型近年的快速发展，使研究重点逐步从"单步回答是否正确"转向"跨越更长时间尺度的行为是否连续、稳定且可解释"。长时序任务中的困难并不只是动作数量增加，更在于错误会跨回合传播：一次看似轻微的误判，可能在几十步之后表现为迷路、剧情锁死、资源浪费，或者上下文持续偏移。与纯文本环境相比，游戏环境更容易把这类问题暴露出来，因为它同时要求模型处理空间导航、UI 状态切换、图像观察、脚本触发和资源约束[17]。

《宝可梦 红》适合作为研究对象，是因为它把上述困难压缩进一条短而密集的早期主线。玩家需要离开大木博士研究所、通过真新镇北口、穿越 1号道路、到达常磐市，并在常磐市友好商店中完成关键交互。这个过程看似简单，实际却同时包含门口对齐、狭窄路径调整、文本推进、菜单切换和野战处理。一旦模型在这些局部步骤上判断失误，就很容易出现反复撞墙、原地循环、错过剧情触发点等问题。

JRPG 中常见的失败并不是"完全不知道目标是什么"，而是"知道大致目标，却无法把一连串细小动作稳定地做对"。因此，这类任务的研究价值在于检验模型是否能够在固定起点、有限预算和严格日志约束下，多次给出方向一致的连续决策。基于这一点，本研究特别强调结构化时间线、动作来源记录和里程碑证据，而不是只展示若干成功截图。

### 1.2 国内外研究现状

**强化学习游戏智能体方面**，以 DQN[2]、AlphaZero[19]和 AlphaStar[9]为代表的训练型方法已在 Atari、棋类和即时战略游戏中取得突破性成果。OpenAI Five 进一步在 Dota 2 中展示了大规模分布式强化学习在高度复杂、部分可观测环境中的竞争力[22]。这些工作确立了游戏环境作为评估连续决策能力的核心场景。在评估基准方面，从早期的 Arcade Learning Environment[1]、Procgen[11]到面向文本交互的 TextWorld[18]和 Interactive Fiction Games[21]，再到面向开放世界的 MineDojo[16]以及面向 LLM 智能体的 SmartPlay[20]，研究社区已逐步建立起覆盖不同任务复杂度和观测模态的评测体系。在文本游戏领域，基于图结构的深度强化学习方法已经证明知识图谱对状态追踪的辅助价值[24]。Yannakakis 和 Togelius 对游戏人工智能的系统梳理[17]表明，游戏 AI 研究正从追求单一基准上的性能转向关注跨任务迁移能力和运行时可解释性。

**大语言模型智能体方面**，GPT-3 展示的少样本任务迁移能力[3]为将语言推理引入交互式决策提供了基础。链式思维提示[4]和零样本推理[23]表明，显式的中间推理步骤能够显著提升复杂任务表现。在此基础上，思维树方法将推理过程组织为可搜索的树结构，进一步增强了多步规划能力[14]。在行动规划方向，Huang 等人证明大语言模型可以作为零样本规划器，从语言描述中提取可执行的行动知识[15]。在长时序交互领域，Generative Agents 强调长期记忆与摘要压缩[5]，ReAct 将推理链与行动链耦合[6]，Reflexion 和 Voyager 进一步展示了结构化经验积累对复杂任务表现的价值[7-8]。Carta 等人在交互式环境中将大语言模型与在线强化学习结合，探索了两种范式的互补性[16b]。

**面向游戏的 LLM 直接决策方面**，现有工作多集中在 Minecraft 等开放世界[8,16]或文本冒险游戏[18,21]中，研究重点往往是能力展示或代表性案例，较少涉及按钮级执行精度、结构化时间线核验和小样本批量复验。在《宝可梦 红》环境中，已有基于强化学习的研究揭示了地图探索、脚本触发和奖励稀疏等核心难点[10]，但以大语言模型直接承担逐回合决策、并在封闭 JRPG 环境中建立可审计证据链的工作尚属空白。本文正是在这一交叉点上展开研究。

### 1.3 研究问题

本文围绕两个可以直接落到系统实现与实验验证上的问题展开。

`RQ1`：在固定起点、有限预算和主模型主导的运行协议下，系统能否在《宝可梦 红》早期主线中完成非平凡推进，并留下可核验的结构化证据？

`RQ2`：在当前早期剧情窗口内，故事引导、战斗引导以及相关运行时支撑对推进稳定性呈现出怎样的作用差异？

### 1.4 研究目标与贡献

围绕上述问题，本文的研究目标是构建一套面向《宝可梦 红》早期主线的直接决策型大语言模型游戏智能体系统，并在统一实验条件下对其推进能力进行结构化检验。为实现这一目标，本文首先搭建了完整的运行平台，集成 `PyBoy` 模拟器接入、RAM 语义状态提取、`GameState` 任务化状态构造、地图记忆、上下文管理、主模型决策链、动作执行层、可视化界面和结构化报告管线，使"从模拟器状态到模型动作，再到证据输出"的全过程能够被连续追踪。

在此基础上，本文给出了以普通回合主模型直接决策为核心的运行协议与评估口径，明确区分模型动作生成、运行时状态支持与可开关引导文本三者的职责边界。实验方面，本文在主实验统一初始状态下完成了 `120` 回合完整引导条件下的小样本批量复验、`260` 回合长程压力测试以及 2 组探索性模块分析，形成了从核心窗口统计到长程瓶颈定位的分层实验结果。同时，本文建立了结构化报告、原始截图、主图、批量汇总表与正文论述之间的对应关系，使正文中的主要结论都能够回溯到具体运行记录。

综合来看，本文的贡献主要体现在两个方面：一方面，完成了一个可运行、可追踪、可复验的直接决策型游戏智能体实验平台；另一方面，围绕故事引导与战斗引导给出了初步的模块化分析结果，揭示了不同支持文本在早期推进窗口中的作用差异。

### 1.5 论文结构

第 2 章讨论本文与生成式智能体、游戏智能体和可审计运行时研究的关系。第 3 章定义任务范围、评价口径与实验约束。第 4 章给出系统设计、已完成模块与复现实验配置。第 5 章说明状态构造、上下文组织、主决策模块以及两类引导模块。第 6 章说明实验协议、统计计划与证据组织原则。第 7 章报告主实验、历史基线对照和消融结果。第 8 章讨论结果的适用范围与研究局限，总结全文并展望后续方向。

## 第 2 章 相关工作与方法定位

### 2.1 长时序生成式智能体

大语言模型在少样本条件下展现出的任务迁移能力[3]以及零样本推理能力[23]，为将语言推理引入交互式决策任务提供了基础。链式思维提示表明，显式中间推理有助于提升复杂任务求解表现[4]；思维树方法将推理组织为可搜索的树结构，提升了多步规划的系统性[14]。在更接近智能体研究的方向上，Huang 等人证明大语言模型可以直接作为零样本规划器[15]，`Generative Agents` 强调长期记忆、摘要压缩与基于相关性的检索机制[5]，`ReAct` 将推理链与行动链耦合起来，使模型能够在环境反馈中连续更新判断[6]，`Reflexion` 和 `Voyager` 进一步展示了结构化经验积累对复杂任务表现的价值[7-8]。这些工作共同说明，若要让语言模型承担长时序任务，单次提示质量并不是唯一关键，如何保存近期历史、提炼任务状态并把推理结果稳定地落实为行动，同样重要。

现有长时序 LLM 智能体研究多数发生在开放任务、文本世界或沙盒环境中[18,21]，研究重点往往是任务完成率或能力展示，较少细究封闭游戏环境中的按钮级执行、地图切换、时间线核验和批量复验。本文借鉴的是这些工作的问题分解方式：将长期记忆落到近期回合与摘要历史，将推理与行动耦合落实到 `MainAgent` 的结构化输出接口，再把地图记忆、引导文本和批量报告纳入统一证据链。本文的工作可以视为将长时序 LLM 智能体路线压缩到一个更窄、更难、也更容易复验的游戏窗口中。

### 2.2 游戏智能体与《宝可梦 红》研究环境

在训练型游戏智能体方向，DQN 展示了从原始像素到动作控制的端到端强化学习路径[2]，AlphaZero 在棋类游戏中实现了不依赖人类知识的自我对弈学习[19]，AlphaStar 表明多智能体强化学习可以在复杂、部分可观测且实时对抗的环境中达到顶尖人类水平[9]，OpenAI Five 则在 Dota 2 中展示了大规模分布式训练在长时序团队协作中的可行性[22]。这些成果确立了游戏环境作为检验连续决策能力的重要场景。在基准环境建设方面，TextWorld[18]和 Interactive Fiction Games[21]为文本交互智能体提供了标准化评估框架，MineDojo[16]在开放世界中构建了多模态任务集合，基于图结构的文本游戏方法则展示了显式知识组织对状态追踪的辅助价值[24]。

对本文而言，`Pokemon Red via Reinforcement Learning`[10]的价值在于揭示了《宝可梦 红》环境本身的难点：地图探索、脚本触发、战斗系统、奖励稀疏性和长链任务组织。本文的系统设计围绕这些难点展开，例如用地图记忆缓解跨地图迷失，用阶段目标维持剧情方向，用统一状态抽象处理战斗与文本切换。

与 `Arcade Learning Environment` 和 `Procgen` 等更强调短程控制或泛化评测的经典基准[1,11]以及 SmartPlay 等面向 LLM 的综合评测框架[20]相比，《宝可梦 红》更突出异构状态之间的频繁切换。在这个环境中，一个看似简单的"向上"动作是否合理，取决于当前是否在门口、是否处于文字框阶段、是否刚结束战斗、是否正在跨地图边界。模型面对的不是单一低层动作空间中的局部优化问题，而是需要在自由移动、对话脚本、战斗文本、战斗菜单和跨地图传送之间反复切换语义解释。基于这一特征，本文把重点放在状态组织是否有效、动作来源是否清晰、关键剧情窗口能否稳定推进上。

### 2.3 可审计运行时支持体系

在模拟器环境中，如果不给模型提供运行时支撑，它几乎每个回合都要从截图重新推断位置、界面状态和当前目标，决策质量很快就会被噪声淹没。研究所门口是否对齐、真新镇北口是否触发转场、文字框是否已经结束、战斗后是否回到可移动状态，这些细节都很难只靠单帧视觉稳定判断。基于这一现实，本文把运行时模块视为研究对象的一部分。

具体来说，本文将运行时支撑划分为观测层、上下文层、执行层和评估层。观测层负责从 RAM 和截图中抽取可用状态；上下文层负责组织近期回合、摘要历史和任务笔记；执行层负责动作合法化、单按钮落实和同回合同观测重试；评估层负责日志记录、时间线校验和批量汇总。这样的划分有两个直接好处：一是"模型负责什么、系统负责什么"在实验口径上保持清楚，二是每个支持模块都能在代码、日志和实验开关中留下可追踪痕迹。基于这一区分，结构化状态、动作合法化和日志审计属于运行时基础设施；故事引导和战斗引导则属于可显式开关、可单独分析的支持文本。

### 2.4 本文的方法定位

基于上述讨论，本文的方法定位为面向长时序 JRPG 的运行时系统研究。核心问题是：在固定起点、有限动作集、严格回合预算和明确日志约束下，LLM 能否稳定承担普通回合决策。围绕这一问题，本文建立了一条从状态组织、动作执行到证据沉淀的完整链路，并把系统实现、实验设计和结果解释统一到同一套实验框架中。具体而言，本文研究的是：在显式运行时支撑和可开关引导文本条件下，由 LLM 直接承担普通回合决策的直接决策型游戏智能体。

如图2-1所示，本文采用基于分类准则的定位方式：首先按照"策略产生方式"区分训练后执行的强化学习游戏代理与依赖在线语言推理的 LLM 智能体，再按照"任务环境"将后者区分为通用任务型 LLM 智能体与本文研究的游戏决策智能体。这一表示方式说明：本文方法的定位来自结构化游戏状态输入、LLM 直接承担普通回合决策以及面向封闭游戏环境的可复验证据组织。

## 第 3 章 任务定义与证据边界

### 3.1 任务范围

本文覆盖的主任务窗口是《宝可梦 红》的早期剧情，从主实验统一初始状态出发，预算为 `120` 或 `260` 回合。记单次运行预算为 $H$，则有

$$
H\in\{120,260\},\qquad
\mathcal{G}=\mathcal{G}_{\text{core}}\cup\mathcal{G}_{\text{ext}},
\tag{3-1}
$$

其中

$$
\mathcal{G}_{\text{core}}=\{g_1,g_2,g_3\},\qquad
\mathcal{G}_{\text{ext}}=\{g_4,g_5,g_6,g_7\}.
\tag{3-2}
$$

本文考察如下里程碑集合：

为避免将项目内部存档名称直接写入论文正文，本文统一将主实验所使用的起始存档称为"主实验统一初始状态"，将历史对照所使用的起始存档称为"历史基线初始状态"。

1. $g_1$：到达 1号道路
2. $g_2$：到达 常磐市
3. $g_3$：进入 常磐市友好商店
4. $g_4$：获得 大木博士的包裹
5. $g_5$：获得 宝可梦图鉴
6. $g_6$：到达 2号道路
7. $g_7$：到达 常磐森林

其中，$\mathcal{G}_{\text{core}}$ 构成本研究最核心的结构化窗口；$\mathcal{G}_{\text{ext}}$ 只作为更远剧情的补充指标，不作为本文主结论的必要前提。

### 3.2 形式化描述

可将该任务视为部分可观测马尔可夫决策过程[12,20]

$$
\mathcal{M}=(\mathcal{S}, \mathcal{A}, \mathcal{O}, T, \Omega, R, \gamma).
\tag{3-3}
$$

系统在每个回合获得观测 $o_t$，其内容包括截图、RAM 提取的高层语义状态、地图记忆摘要、导航摘要与上下文笔记；模型输出离散动作

$$
\mathcal{A}=\{\texttt{up}, \texttt{down}, \texttt{left}, \texttt{right}, \texttt{a}, \texttt{b}, \texttt{start}, \texttt{select}, \texttt{wait}\}.
\tag{3-4}
$$

对预算为 $H$ 的单次运行，记其轨迹为

$$
\tau_H=\{(o_t,a_t)\}_{t=1}^{H},\qquad H\in\{120,260\}.
\tag{3-5}
$$

本文不直接估计环境回报，而将轨迹 $\tau_H$ 上的里程碑到达情况、主模型直接决策占比和时间线有效性作为主评价对象。

### 3.3 观测与动作表示

在本文系统中，单步观测可抽象写为

$$
o_t=\big[x_t^{ram}, x_t^{img}, x_t^{nav}, x_t^{ctx}, x_t^{goal}\big].
\tag{3-6}
$$

其中 $x_t^{ram}$ 表示通过 `MemoryReader` 从 RAM 中读取的结构化状态，$x_t^{img}$ 表示当前截图及其可选视觉提示，$x_t^{nav}$ 表示地图记忆与局部导航摘要，$x_t^{ctx}$ 表示近期回合和摘要历史，$x_t^{goal}$ 表示当前焦点任务和待办事项。与只给一张截图的做法相比，这种多源状态组织方式显著降低了模型对模糊视觉细节的依赖，并使其能够显式利用过去信息。

### 3.4 评价口径

本文使用与运行报告直接对齐的四类指标：

1. 主模型直接决策回合占比

$$
R_{\text{direct}}^{(r)}=\frac{N_{\text{direct}}^{(r)}}{T^{(r)}}
\tag{3-7}
$$

其中，$N_{\text{direct}}^{(r)}$ 表示第 $r$ 次运行中由主模型直接完成决策的回合数，$T^{(r)}$ 表示该次运行的总回合数。

2. 里程碑到达情况

对第 $r$ 次运行和第 $i$ 个里程碑，定义

$$
I_i^{(r)}\in\{0,1\},\qquad
\hat p_i=\frac{1}{n}\sum_{r=1}^{n} I_i^{(r)}.
\tag{3-8}
$$

其中，$I_i^{(r)}=1$ 表示第 $r$ 次运行到达里程碑 $g_i$，否则为 $0$；$\hat p_i$ 为批量实验中的里程碑到达率。

3. 时间线有效性

记第 $r$ 次运行的时间线有效性为

$$
V^{(r)}=m_{\text{mono}}^{(r)}\,m_{\text{state}}^{(r)}\,m_{\text{last}}^{(r)},
\qquad
m_{\text{mono}}^{(r)},m_{\text{state}}^{(r)},m_{\text{last}}^{(r)}\in\{0,1\}.
\tag{3-9}
$$

其中：

1. $m_{\text{mono}}^{(r)}=1$ 表示回合编号保持单调递增；
2. $m_{\text{state}}^{(r)}=1$ 表示报告中的最终状态与结束回合一致；
3. $m_{\text{last}}^{(r)}=1$ 表示时间线记录中的最后一回合与结束回合一致。

4. 补充诊断信息

对长程运行中的补充诊断量，记

$$
N_{\text{cool}}^{(r)},\qquad
N_{\text{err}}^{(r)},\qquad
\bar{\ell}^{(r)}=\frac{1}{T^{(r)}}\sum_{t=1}^{T^{(r)}} \ell_t^{(r)}.
\tag{3-10}
$$

其中，$N_{\text{cool}}^{(r)}$ 为 AI 冷却回合数，$N_{\text{err}}^{(r)}$ 为 AI 调用错误回合数，$\bar{\ell}^{(r)}$ 为平均请求时延，用于定位系统瓶颈。

据此定义两级证据：

$$
E_{\text{valid}}^{(r)}=V^{(r)},\qquad
E_{\text{full}}^{(r)}=V^{(r)}\cdot \mathbf{1}\!\left[R_{\text{direct}}^{(r)}=1\right].
\tag{3-11}
$$

其中，$E_{\text{valid}}^{(r)}=1$ 表示有效运行证据成立；$E_{\text{full}}^{(r)}=1$ 表示全回合主模型直接决策证据成立。

前者说明结构化时间线可核验；后者进一步说明全部普通回合均由主模型直接产出动作，而没有退化为 AI 冷却回合或 AI 调用错误回合。

### 3.5 样本量约束的前置说明

本文主实验的重复次数为 `n=3`，消融实验和长程压力测试均为 `n=1`。这一样本量选择受限于两个现实因素：一是外部模型服务的调用成本——每次 `120` 回合运行需要完成 120 次以上的模型请求，加上调试、预实验和失败重试，总调用量远高于正式实验本身；二是实验周期约束——每次运行需要实际执行模拟器推进并等待模型响应，单次 `120` 回合运行耗时约 12–15 分钟，`260` 回合运行耗时更长，加上需要人工核查时间线和截图，总周期难以支撑大规模重复。

`n=3` 仅足以表达"非零重复现象"和粗略不确定性，能够支持初步可重复性判断，但不足以支撑强统计主张或细粒度比例比较。因此，本文对重复实验报告 Wilson 95% 置信区间以反映二项比例的不确定性，对单次运行采用探索性描述而非确认性推断。读者在解读实验结果时应将这一样本量约束作为前提条件。

*表3-1 主实验支持机制归类*

| 机制 | 归类 | 作用 |
| --- | --- | --- |
| RAM 只读状态提取 | 观测支持 | 提供结构化语义状态，不直接生成动作 |
| 地图记忆与导航摘要 | 状态组织支持 | 压缩历史轨迹、探索边界与局部导航信息 |

注：检查点恢复仅用于统一实验初始条件；直接替代普通回合主模型决策的机制不纳入主实验统计。

### 3.7 主模型直接决策运行协议的工作定义

在本文中，"主模型直接决策运行协议"是一个针对动作生成来源的实验定义：普通回合的最终动作由主模型直接给出，系统通过可审计的方式提供观测组织、执行稳定化和结果记录。基于这一工作定义，本文把 RAM 只读状态提取、地图记忆、上下文摘要和动作合法化视为运行时基础设施，把故事引导和战斗引导视为可开关、可单独分析的支持文本，并通过日志字段持续记录决策来源、主模型直接决策占比与时间线有效性。这样定义的优势在于：既能够完整呈现系统已经实现的状态组织与执行能力，也能够在实验中把模型动作生成、运行时支持和引导文本三者的作用区别开来。

### 4.5 系统单回合运行流程

从单个回合的执行流程来看，系统已经形成了一条较为清晰的闭环。

1. 模拟器读取当前截图、RAM 状态、地图位置、事件位和基础环境信息。
2. `GameState` 联合地图记忆与近期结果，将原始观测整理成任务化状态文本。
3. `ContextManager`、`Summarizer` 和 `GoalManager` 补充近期回合、历史摘要、任务笔记和当前阶段目标。
4. `MainAgent` 基于完整上下文输出屏幕判断、决策理由、执行动作、短程动作计划和目标更新。
5. `DecisionEngine` 记录路径来源并将动作交给 `ActionExecutor` 执行到模拟器。
6. 执行结果、截图、时间线记录和结构化字段被写入日志与报告，为后续批量汇总、图像整理和实验复盘提供基础。

这一流程把观测组织、模型决策、动作执行和证据沉淀整合成了一个可以持续重复运行的闭环。

### 4.6 复现实验说明

主实验采用无界面模式运行，并在每份单次报告中记录 `environment`、`effective_settings`、`config_snapshot` 与 `report_validation`。这使得读者可以追踪所用模型、主要实验开关、时间线是否完整，以及结尾状态是否与最后一回合一致。正文据此整理出关键信息，便于读者直接理解系统配置与实验条件。

## 第 5 章 核心方法与关键模块

### 5.1 任务化状态构造（GameState）

任务化状态构造模块（`GameState`）将 RAM、UI 状态、截图元信息、队伍信息、事件位和地图记忆组合为任务化文本状态。这一层的作用，是把模型在长上下文中需要持续维护的局部事实显式化，例如当前位置、邻接方向是否被证实阻塞、当前是否仍处于战斗文本、当前网格的访问次数、最近的前沿候选等。

### 5.2 地图记忆与导航摘要

地图记忆模块持续记录已探索网格、已知出口、确认阻塞方向、传送点与前沿候选。其输出采用摘要形式，为模型提供稳定的空间先验。对于长时序导航而言，这一模块的核心价值在于减少重复探索和局部循环，并帮助模型把注意力放到真正可扩展的方向上。

### 5.3 上下文压缩与任务笔记

长时序运行中，模型最容易丢失的是阶段目标、当前位置与近期失败尝试之间的联系。因此系统显式保留近期回合、历史摘要和任务笔记，并将它们组织成主模型每回合都能直接读取的上下文。由此，模型在大木博士研究所、真新镇和 1号道路等关键区域，不仅能够利用当前状态，还能继承上一回合动作、当前阶段目标以及近期失败方向等对连续决策十分关键的信息。

### 5.4 主模型决策模块（MainAgent）

主模型决策模块（`MainAgent`）负责读取任务化状态、近期回合和引导说明，并输出当前屏幕判断、决策理由、执行动作、短程动作计划和目标更新。借助这种结构化输出，系统能够在导航、文本推进和战斗菜单切换之间保持统一的决策接口，同时为后续报告保留可分析的决策理由字段和目标更新记录。

### 5.5 决策调度模块（DecisionEngine）

决策调度模块（`DecisionEngine`）是主模型直接决策运行链路中的调度与审计核心。它负责维持实验模式、协调 `GameState` 与 `MainAgent` 之间的调用、记录每回合决策来源，并将动作安全地交给执行层。借助这一层，系统可以把"模型产出动作""运行时执行动作""日志记录决策来源"三个过程稳定地串联起来。

为了形式化这一调度层在实验分析中的作用，本文保留逐回合决策来源记录与主模型直接决策占比两个概念。对一段长度为 $T$ 的轨迹 $\tau=\{1,\dots,T\}$，定义

$$
R_{\text{direct}}(\tau)=\frac{N_{\text{direct}}(\tau)}{|\tau|}.
\tag{5-1}
$$

其中，$N_{\text{direct}}(\tau)$ 表示轨迹 $\tau$ 中由主模型直接完成决策的回合数，$|\tau|=T$ 表示轨迹长度；逐回合来源记录则用于区分主模型直接决策、AI 冷却和 AI 调用错误等情况，为后续问题定位提供依据。

为避免将实现细节展开成过宽表格，表5-1仅保留主路径涉及的核心模块、接口要点与职责概括。

### 5.6 场景控制器与主实验协议的关系

系统代码中保留了面向特定剧情段的场景控制器（如大木研究所选择宝可梦控制器、宿敌战控制器、常磐市取包裹控制器等共 8 个），这些控制器设计用于更早期的混合决策协议阶段，能够在检测到特定地图位置和游戏状态时接管当前回合的动作生成。在主实验协议下，配置文件中的 `pure_llm_mode` 和 `disable_runtime_fallbacks` 两个开关均设为 `true`。系统在初始化决策引擎时检查这两个标志，若任一为真则将 `DecisionEngine` 的决策阶段列表置为空，所有场景控制器均不被注册到运行时决策链中。因此，主实验中每个普通回合的动作均直接来自主模型调用，不存在场景控制器隐式接管的情况。即使在 AI 调用失败时，系统也不会退化为控制器决策，而是如实记录为 AI 冷却回合或 AI 调用错误回合。

这一设计使得主实验中主模型直接决策回合占比 `1.0` 的口径与代码实现严格一致：`decision_source` 字段在全部普通回合中均记录为 `"ai"`，而非来自任何场景控制器。这些控制器在历史基线阶段（第 7.3 节）曾参与混合决策，其逐步退出也构成了从早期混合协议向主模型直接决策协议演进的工程脉络。

### 5.7 动作执行层（ActionExecutor）与稳定化

动作执行层（`ActionExecutor`）负责把主模型输出的高层动作记号稳定映射为模拟器中的有效操作。在 Game Boy 一类低分辨率、按键驱动的环境中，同一个方向动作在不同帧上下文中可能产生朝向变化、格点位移、文本推进或菜单焦点移动等不同效果。执行层的核心价值，是把已经生成的动作稳定落实到模拟器中，并保持"一次决策对应一次可审计执行"。

在主实验协议下，`ActionExecutor` 服从"单按钮执行约束"：非精确模式下的普通回合原则上只落实一次主按钮输入，不将单次模型决策扩展为多步自动寻路、连续策略性连按或额外动作规划。必要的稳定化帧处理仍然允许存在，但其作用仅限于保证按钮输入被模拟器正确接收，而不改变该回合的动作语义。这样的约束使"模型负责什么、执行层负责什么"在实验口径上保持清楚。

### 5.8 故事引导与战斗引导

系统包含两个可显式开关的引导模块。它们的作用，是把与该窗口高度相关的任务信息以前馈文本的方式组织给主模型，从而提高长时序决策中的阶段一致性。

故事引导根据早期地图位置和事件位生成窄域提示文本。例如在大木博士研究所中，它会给出门口位置等与离开房间直接相关的信息；在真新镇和 1号道路中，它会提供早期主线的已验证走向。借助这一模块，系统能够把当前地图阶段最关键的剧情目标更直接地呈现给主模型，从而减少在关键路口和门口附近的无效徘徊。

战斗引导则更多来自 RAM 战斗相位、菜单状态和可用招式信息。它通常提供"当前处于战斗文本阶段，应继续按 A"或"菜单出现时优先选择 FIGHT，再选第一个可用伤害招式"之类的局部提示文本。借助这一模块，系统能够在战斗文本、菜单选择和普通移动之间切换得更稳定，使同一条主决策链能够覆盖自由探索与战斗交互两类场景。

从方法边界看，故事引导和战斗引导都属于可显式开关的支持文本，而非模型在本文实验中自行获得的内生知识。因此，完整引导条件下的结果反映的是模型在结构化状态和任务支持文本共同作用下的决策表现。本文通过两组单次开关实验考察这两类支持文本在该窗口中的作用差异，相应结果在第 7 章中给出。

### 5.9 同回合同观测重试

主实验允许同回合同观测重试：当模型调用遭遇短暂传输异常时，系统可以在同一观测上重新请求模型，直到达到次数或时间预算上限。这一机制既提高了真实外部模型服务环境下的运行连续性，又能把重试耗尽后的情况明确记录为 AI 调用错误回合，从而保持整条实验时间线的可解释性。

### 5.10 本章小结

综合来看，第 5 章完成的是一条完整的"状态组织 - 上下文维护 - 主模型决策 - 动作执行 - 日志记录"方法链。`GameState`、地图记忆和上下文管理负责把游戏环境整理成可用于长时序决策的输入，`MainAgent` 和 `DecisionEngine` 负责形成统一的决策接口与路径记录，`ActionExecutor`、故事引导、战斗引导和同回合同观测重试则负责提升关键阶段的执行稳定性与运行连续性。这些模块共同构成了本文后续实验结果的工程基础。

### 6.3 统计计划

对于重复实验中的二项比例，本文采用 Wilson 95% 区间：

$$
\operatorname{CI}_{95\%}^{\text{Wilson}}(\hat p_i)=
\frac{\hat p_i+\frac{z^2}{2n}\pm z\sqrt{\frac{\hat p_i(1-\hat p_i)}{n}+\frac{z^2}{4n^2}}}{1+\frac{z^2}{n}},
\qquad z=1.96.
\tag{6-2}
$$

对于时延和比例类连续值，本文报告

$$
\bar{x}=\frac{1}{n}\sum_{r=1}^{n}x^{(r)},\qquad
s_x=\sqrt{\frac{1}{n-1}\sum_{r=1}^{n}\left(x^{(r)}-\bar{x}\right)^2},
\tag{6-3}
$$

并同时给出中位数与极值。如第 3.5 节所述，`n=3` 仅足以支持初步可重复性判断；`n=1` 的消融更适合用来揭示模块敏感性，而不是给出稳定的效应估计。因此，本文在统一起点与统一预算下以区间估计和描述性分析为主，而不对不同条件作强统计比较。

### 6.4 视觉证据与结构化证据的关系

本文将结构化报告、代表性演示运行和补充材料组织为互补的三层证据体系。其中，结构化报告承担正文主统计作用，代表性演示运行承担视觉连续性说明，附录和补充材料则提供原始图像、视频和索引入口。

为避免结构化报告、视频演示和补充材料各说各话，本文对实际使用的证据层次做了统一整理。各层所对应的实验条件已在前文分别说明，表6-2仅保留证据层、主要载体与正文作用。

### 7.2 对长程压力测试的解释

单次 `260` 回合长程运行不能用来给出稳定统计结论，但它对定位系统瓶颈非常重要。与 `120` 回合复验相比，这次运行把观察窗口继续向后拉长，使冷却回合、请求时延和模型服务波动不再只是偶然噪声，而成为能够被单独讨论的系统变量。该次运行虽然保留了完整时间线记录，但推进主要停留在 1号道路。若记该次长程运行的诊断向量为

$$
d_{\text{stress}}=\big(R_{\text{direct}},N_{\text{cool}},N_{\text{err}},\bar{\ell}\big),
\tag{7-2}
$$

则有

$$
d_{\text{stress}}=(0.6154,94,6,7.49\text{s}).
\tag{7-3}
$$

从数值上看，`94` 个 AI 冷却回合和 `6` 个 AI 调用错误回合合计 `100` 回合，占总预算的 `38.46%`。这与 `0.6154` 的主模型直接决策回合占比正好互为补充：约有五分之二的回合并没有形成正常的主模型决策。这一区分说明长程运行当前暴露出的首要问题不是时间线损坏或剧情语义失控，而是外部模型服务的可用性和时延波动持续打断了行动链条。长程测试更像一次系统稳定性测试，而不是与 `120` 回合复验完全同口径的成功率比较。

因此，这次长程压力测试的意义主要有两点：一是揭示了更远剧情窗口中的真实瓶颈画像，二是表明在解释长时序表现时必须同时区分"游戏内决策错误"和"系统外部依赖失稳"两类失败来源。

从本文结果看，故事引导对早期路线形成更为敏感，而战斗引导在本窗口中更多承担局部语义稳定化作用。以下对两组消融结果作进一步解释。

**关闭故事引导的效果**。关闭故事引导后，系统在 120 回合内未能离开大木博士研究所区域，并出现了 `2x2` 微循环警告。这一结果表明，在早期剧情最初阶段，模型在缺少窄域定向文本时难以准确判断门口位置和离开路线。故事引导在该阶段的作用类似于人类玩家对游戏初始流程的先验知识——例如"门在下方"、"出门后向上走"等信息，这些对于有经验的玩家是常识，但对于仅依赖视觉和 RAM 状态的模型而言并非显然。同时，该次运行的主模型直接决策占比降至 `0.9167`（出现 `10` 个 AI 冷却回合），这意味着在缺少故事引导的条件下，模型在反复尝试中偶尔触发了外部服务异常，进一步打断了决策链条。

**关闭战斗引导的效果**。关闭战斗引导后，单次运行反而到达了全部三个核心里程碑，表面上看甚至"优于"完整引导条件下的 `2/3` 到达率。但这一比较在统计上不成立：完整引导条件的 `2/3` 来自 `n=3` 的批量统计，而关闭战斗引导仅为 `n=1` 的单次观察。在 `n=1` 条件下，运行结果高度依赖该次运行的具体随机种子（包括野战遭遇概率、模型在关键路口的具体输出等），无法与批量统计直接比较。此外，在 120 回合、早期剧情的窗口内，系统遭遇野战的概率本身较低——1号道路区间较短，许多运行可能在未遇到或仅遇到少量野战的情况下就已到达常磐市。因此，关闭战斗引导在该窗口内未产生明显负面影响，符合"战斗引导在当前窗口中并非主推进瓶颈"的判断。随着任务窗口向后扩展（如进入常磐森林等高遭遇率区域），战斗引导的作用可能显著增大。

需要强调的是，两组消融均为 `n=1` 单次运行，其结论应理解为方向性信号而非稳定的效应估计。将故事引导和战斗引导分别扩展为小样本重复消融，是后续工作中优先级较高的任务。

### 7.6 结果层次化总结

将本章结果综合来看：证据强度最高的是完整引导条件下的 `120` 回合重复实验，它们直接支撑了"系统能够从统一起点重复推进到 1号道路，并在多数情况下继续到达常磐市与常磐市友好商店"这一主结论。证据强度次之的是长程压力测试和代表性演示，它们说明系统具备向更远剧情节点延伸的潜力，同时也把长程运行中的薄弱环节暴露得更清楚。再次之，探索性模块分析和历史阶段材料有助于解释这些结果为什么出现，以及协议演进改善了什么。

因此，本章支持的结论是：系统已经在早期核心窗口内形成了可复验的推进能力，并且具备继续向后扩展的明确工程路径。

### 7.7 成本、时延与平台成熟度

对完整引导重复实验的请求时延，记统计量为

$$

### 7.8 小结

第 7 章围绕核心里程碑窗口建立了可重复统计、扩展示例和解释性材料三层互补证据。围绕 1号道路、常磐市和常磐市友好商店的结果，论文同时给出了结构化统计、图像补充和协议演进参照。

## 第 8 章 讨论与结论

### 8.1 结果的适用范围

本文经过最充分结构化复验的窗口，是从主实验统一初始状态出发，到 1号道路、常磐市和常磐市友好商店的早期主线推进。围绕这一窗口，论文拥有批量统计、图像主图、原始运行记录和模块分析四类互补材料，可以较有把握地回答"早期窗口是否具备可重复推进能力"这一问题。

本文结论的边界同样清楚。首先，最强证据集中在 `120` 回合预算内的核心窗口，不能据此直接推断更远剧情节点也已达到同等稳定性。其次，样本规模偏小（主实验 `n=3`，消融与长程测试 `n=1`），消融与长程测试承担的是解释作用而非严格统计比较。再次，故事引导和战斗引导代表了一定程度的人工先验支持，完整引导条件下的结果反映的是模型与支持文本共同作用的表现。更远的剧情节点（大木博士的包裹、宝可梦图鉴、2号道路与常磐森林）在本文中承担代表性演示与扩展观察的角色。

### 8.2 研究局限

本文存在以下主要局限：

1. **样本量不足**。`n=3` 的重复实验仅能支持初步可重复性判断，Wilson 95% 置信区间宽度较大（如常磐市到达率 `[20.8%, 93.9%]`），不足以支撑细粒度的比例比较或条件间差异检验。消融实验 `n=1` 只能提供方向性信号。

2. **缺少同条件基线**。本文未在相同实验初始状态下设置随机动作基线或其他 LLM 基线，难以定量回答"相对于无模型的随机策略，系统的提升幅度是多少"。历史基线虽然展示了协议演进方向，但初始状态不同，不构成严格可比的对照。

3. **外部模型服务依赖**。系统依赖第三方 API 提供模型推理服务，模型的实际行为受 API 端的负载、版本更新和路由策略影响。长程压力测试中 `38.46%` 的非正常回合占比已经表明这一依赖对实验稳定性的实质影响。

4. **引导文本的人工先验成分**。故事引导中包含人工编写的早期剧情定向信息，这意味着系统目前尚未实现完全自主的路线发现。在评估模型"自主决策能力"时，需要将这一前提纳入考量。

### 8.3 进一步研究方向

后续研究可围绕三个方向展开。第一是补充可比性：在相同实验初始状态下设置随机动作基线和同条件 LLM 基线，并将故事引导和战斗引导分别扩展为小样本重复消融（`n>=3`），以更清楚地量化不同支持机制的效应。第二是扩大样本量：将 `120` 回合批量复验扩展至 `n>=10`，以获得更稳定的比例估计、更窄的置信区间和更可靠的异常回合分布。第三是延伸任务窗口：继续向大木博士的包裹、宝可梦图鉴、2号道路与常磐森林推进，并逐步压缩故事引导中的人工先验成分，同时针对外部模型服务波动优化长程运行稳定性。更合适的推进顺序是"先补可比性，再补样本量，最后拉长窗口"。

### 8.4 结论

本文围绕《宝可梦 红》早期主线，完成了一套运行于 `PyBoy` 上的大语言模型游戏智能体系统。系统实现了 RAM 语义状态提取、任务化状态构造、地图记忆、上下文组织、主决策链、动作执行层、可视化界面和结构化评估管线，并将这些模块统一到同一套主模型直接决策实验框架中。系统具备从模拟器状态读取、到模型决策、再到结构化取证的完整闭环。

核心实验结果来自主实验统一初始状态下、完整引导条件中的 `120` 回合小样本批量复验（`n=3`）：`3/3` 到达 1号道路，`2/3` 到达常磐市，`2/3` 进入常磐市友好商店，且各次运行的主模型直接决策回合占比均为 `1.0`，时间线记录均有效。这一结果表明，系统在所考察的早期窗口内具备初步的可重复推进能力。长程压力测试和代表性演示补充说明了系统向后续剧情延伸的潜力，同时也揭示了外部模型服务稳定性对长时程表现的制约。

本文的价值在于把一个容易停留在演示层面的系统整理成了可被论文检验的研究对象：结论有明确窗口，证据有清楚来源，局限能够被直接指出。未来工作将围绕同条件基线、重复样本扩充和更远剧情窗口推进展开，并逐步降低人工引导在系统中的权重，以进一步检验系统在更长时序任务中的稳定决策能力。
